Java 单例设计模式

整理饿汉式、懒汉式、双重检查锁和静态内部类等单例实现。

设计模式概念最早来源于建筑。这里的设计模式是在软件开发过程中的设计模式。

设计模式是经验的总结，通过在开发过程中我们发现每一个解决方案可以解决某一类问题，
为了技术交流的方便，为每一个解决方案起了个名称（设计模式）。
注意：设计模式是需要大家通过经验的积累而获得的。

软件开发的设计模式分为三类（23 种）
1：创建型（创建类或对象的：例如：单例、工厂）
2：结构型（关注类的结构）
3：行为型（关注类的行为）

单例：（单一的实例）
也就是说：在整个项目（的运行）中某个类的实例只有一个。
单例的目的：通过一个对象的使用（节省内存，提高效率）

实现（解决创建多个的问题）

1：私有化构造器（防止在类的外部创建对象）
2：私有的静态成员
3：公共的静态的创建对象的方法（全局访问点）

饿汉模式

加了final线程安全，不加final线程不安全

懒汉模式（线程安全）

DCL单例（双重检查锁Double Check Lock）

静态内部类单例

推荐在以下场景使用枚举单例：

  1. 需要简单、安全的单例实现
  2. 不需要继承其他类
  3. 需要防止反射和反序列化攻击
  4. 希望代码简洁易维护

使用枚举实现单例模式是一种非常优秀的方式，它提供了：

  • 天然的线程安全性
  • 防止反射和反序列化攻击
  • 简洁的代码实现
  • 延迟初始化

虽然枚举单例有一些局限性（如不能继承其他类），但在大多数情况下，它是实现单例模式的最佳选择。特别是在需要高度安全性的场景下，枚举单例比其他实现方式更加可靠
