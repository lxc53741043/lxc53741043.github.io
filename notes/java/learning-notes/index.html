str1.equals(str2)

  • 功能：用于比较两个字符串的内容是否相同。
  • 行为：equals() 方法会逐个字符比较两个字符串的内容。如果两个字符串的长度相同，并且每个对应位置的字符都相同，则返回 true；否则返回 false。
  • 用途：当需要比较两个字符串的 内容 是否相同时，应该使用 equals() 方法。

str1 == str2

  • 功能：用于比较两个字符串对象的 内存地址 是否相同。
  • 行为：== 运算符会检查两个字符串变量是否指向同一个对象。如果两个变量指向同一个对象，则返回 true；否则返回 false。
  • 用途：== 通常用于比较对象的引用是否相同，而不是比较内容。在字符串比较中，如果需要比较内容，应该使用 equals()。

public class Car{
    private String color;
    private int year;
    
	public Car(String color) {
    this.color = color;
    this.year = 2023; // 默认年份
}

public Car(String color, int year) {
    this(color); // 调用单参数构造器
    this.year = year; // 覆盖默认年份
}

public void printDetails() {
    System.out.println("Color: " + color + ", Year: " + year);
}

public static void main(String [] args) {
    Car car1 = new Car("Red");
    Car car2 = new Car("Blue", 2020);
    car1.printDetails(); // 输出: Color: Red, Year: 2023
    car2.printDetails(); // 输出: Color: Blue, Year: 2020
	}
}

关于 final

  • final 关键字用于声明变量 b 为常量，表示 b 变量在初始化后不能被重新赋值。

  • 但是，final 关键字只限制变量的引用不能改变，不阻止修改变量所指向的对象的属性。

  • 因此，虽然 b 变量是 final 的，但 b.val 的值可以被修改。

方法覆盖（重写）

（重写）指子类重写父类的方法，使得子类对象在调用该方法时，执行的是子类的实现，而不是父类的实现。这是动态绑定（Dynamic Binding）的一个典型例子

方法重载

​ 方法重载是指在同一个类中定义多个同名方法，但这些方法的参数列表不同（参数的数量、类型或顺序不同）。

​ 重载与返回值无关，只看方法名和参数列表

​ 方法重载是静态绑定的一个典型例子，即在编译时确定调用哪个方法

多态与方法重载的区别

特性 多态（方法覆盖） 方法重载
定义 子类重写父类的方法 同一方法名，不同参数列表
绑定类型 动态绑定（运行时） 静态绑定（编译时）
参数列表 必须相同 必须不同
返回类型 必须相同或兼容 可以不同
使用场景 子类需要改变父类方法的行为 提供多种方法实现，根据参数选择

内存机制和数据类型在内存中的情况

引用数据类型内存

对象本身存到堆，变量存的是这个对象的地址值

​ 在创建 Student 对象时，实际创建了两个东西，一个是栈内存中的变量 stu，存储的是类 Student 对象的地址值。一个是堆内存（数据区域）中的 Student 对象本身。在堆内存中的对象本身中，自身的属性变量（Field）并不是存放在栈内存中的，同样也是存放在堆内存中的。对于基本数据类型的变量（Filed）来说，变量存放的是具体的值，对于引用数据类型的变量（Field）来说，存放的同样是该类型指向的具体类型的地址值。引用变量都是指向堆内存里的对象。引用变量与 C 语言里的指针很像，都是存储一个地址值。

interrupt()方法

很多人看到 interrupt() 方法，认为“中断”线程不就是让线程停止嘛。实际上， interrupt() 方法实现的根本就不是这个效果，

interrupt()方法更像是发出一个信号，这个信号 会改变线程的一个标识位属性（中断标识），对于这个信号如何进行响应则是无法确定的（可以有不同的处理逻辑）。很多时候调用 interrupt() 方法非但不是为了停止线程，反而是为了让线程继续运行下去。设置线程中断不影响线程的继续执行

interrupt() 方法的作用：设置该线程的中断标志为 true 并立即返回（该线程并不一定是当前线程，而是指调用该方法的 Thread 实例所代表的线程），但线程实际上并没有被中断而会继续向下执行，会由用户自己决定要不要终止线程以及什么时候终止线程；如果线程因为调用了 wait 系列函数、join 方法或者 sleep 方法而 被阻塞挂起，其他线程调用该线程的 interrupt()方法会使该线程抛 InterruptedException 异常而返回。

interrupt()是实例方法，是调用该方法的对象所表示的那个线程的 interrupt()。

boolean isInterrupted()

isInterrupted()方法的作用：只判断此线程是否被中断 （此线程指的是调用isInterrupted()方法的Thread实例所代表的线程），是则返回true，否则返回false，不清除中断状态。

如果线程还没有 start 启动，或者已经消亡，那么返回依然是 false。中断状态只代表是否有线程调用中断方法，并不代表这个线程是否在运行。

isInterrupted()是实例方法，是调用该方法的对象所表示的那个线程的isInterrupted()

static boolean interrupted()

interrupted()方法的作用：判断当前线程是否被中断（检查中断标志）（注意，这里指的是当前线程，不是调用该方法的Thread实例所代表的线程），返回一个boolean（当前的中断标志），被中断则返回true，否则返回false。并清除中断状态（将中断标志设置为false）。因为该方法是static方法，内部是获取当前调用线程的中断标志而不是调用interrupted()方法的实例对象的中断标志。

这里有一点需要注意，调用interrupted()方法时，它会先记录下当前的中断标志位，然后才会去清除中断状态，也就是将中断标志位设置为false，最后返回之前记录的中断标志位。也就是说如果在调用interrupted()方法前当前线程已经中断了（中断标志为true），那么第一次调用interrupted()方法返回的就是true，但是第一次调用之后当前线程的中断标志就被interrupted()方法设置为false了，所以第二次再调用interrupted()方法时中断状态已经被清除，将返回一个false。

关于这三个方法，

interrupt()是给线程设置中断标志；

interrupted()是检测中断并清除中断状态；

isInterrupted()只检测中断。

还有重要的一点就是interrupted()作用于当前线程，

interrupt()和isInterrupted()作用于此线程，即代码中调用此方法的实例所代表的线程

Park

要permit为1或者中断状态为true，那么执行park就不能够阻塞线程。park只可能消耗掉permit，但不会去消耗掉中断状态。所以能够使用park()阻塞的线程，它的premit一定为0，并且中断状态一定是false。调用过park()的线程，不管是有没有进行阻塞，不管是因为中断而结束的阻塞，还是因为unpark而结束的阻塞，只要调用了park()方法，到最后permit一定为0（因为在开始和结束位置都去消费了permit）

调用过unpark()的线程，最后permit一定为1

JAVA内存模型

关于主内存与工作内存之间具体的交互协议，Java虚拟机定义了8种原子操作：

  1. lock（锁定）：作用于主内存的变量，它把一个变量标识为一条线程独占的状态。
  2. unlock（解锁）：作用于主内存的变量，它把一个处于锁定状态的变量释放出来，释放后的变量才可以被其它线程锁定。
  3. read（读取）：作用于主内存的变量，它把一个变量的值从主内存传输到线程的工作内存中，以便随后的load动作使用。
  4. load（载入）：作用于工作内存的变量，它把read操作从主内存中得到的变量值放入工作内存的变量副本中。
  5. use（使用）：作用于工作内存的变量，它把工作内存中一个变量的值传递给执行引擎，每当虚拟机遇到一个需要使用的变量的值的字节码指令时，执行这个操作。
  6. assign（赋值）：作用于工作内存的变量，它把一个执行引擎接收到的值赋给工作内存的变量，每当虚拟机遇到一个给变量赋值的字节码指令时，执行这个操作。
  7. stroe（存储）：作用于工作内存的变量，它把工作内存中一个变量的值传送到主内存中，以便随后的write操作使用。
  8. write（写入）：作用于主内存的变量，它把store操作从工作内存中得到的变量的值放入主内存的变量中。

Volatile

原子性

定义：一个操作不可拆分、不被中断，要么全部执行，要么都不执行。

volatile并不能保证原子性

synchronized关键字可以保证原子性，因为被synchronized修饰的方法或代码块，在进入之前都加了锁，同一时刻，有且仅有一个线程能执行被“锁”住的代码片段，这就保证了它内部的代码可以全部被执行，所以它具备原子性（基于monitorenter和monitorexit指令实现）

ps：数据库中ACID的原子性指的是“要么都执行要么都回滚”，这是两个不同的概念

线程可见性

定义：指多个线程之间共享数据的可见性。即当一个线程修改了共享变量时，其它线程能立即看到这个修改。

指令重排序

理解 DCL 中 volatile 的必要性：指令重排序问题

instance = new Config() 这行代码的问题不在于类加载机制，而在于 指令重排序 和 内存可见性 问题。

对象创建过程的分解

当执行 instance = new Config() 时，JVM 实际上会执行多个步骤：

  1. 分配内存空间：为 Config 对象分配内存
  2. 初始化默认值：将对象的字段设置为默认值（0、false、null等）
  3. 执行构造方法：调用 Config 的构造方法，进行真正的初始化
  4. 赋值引用：将 instance 变量指向新创建的对象

指令重排序的问题

关键问题在于：JVM 和处理器可能会对这些步骤进行重排序优化，可能会按照这样的顺序执行：

  1. 分配内存空间
  2. 赋值引用（此时 instance 不为 null）
  3. 执行构造方法（真正的初始化）

这种重排序在单线程环境下没有问题，但在多线程环境下会导致严重问题。

多线程场景下的问题

假设没有使用 volatile，两个线程同时调用 getInstance()：

  1. 线程 A 进入同步块，开始执行 instance = new Config()
  2. JVM 重排序指令：先分配内存，然后将引用赋值给 instance，但尚未执行构造方法
  3. 此时线程 B 检查 if (instance == null)，发现 instance 不为 null
  4. 线程 B 直接返回 instance，但此时对象尚未完全初始化！
  5. 线程 B 开始使用这个”半成品”对象，可能导致不可预知的行为

volatile 如何解决这个问题

使用 volatile 关键字修饰 instance 变量时：

  1. 禁止指令重排序：确保对象完全初始化后才将引用赋值给 instance
  2. 保证内存可见性：确保一个线程对 instance 的修改对其他线程立即可见

具体来说，volatile 会在写操作前后插入内存屏障，防止编译器和处理器对指令进行重排序。

设计模式概念最早来源于建筑。这里的设计模式是在软件开发过程中的设计模式。

设计模式是经验的总结，通过在开发过程中我们发现每一个解决方案可以解决某一类问题，
为了技术交流的方便，为每一个解决方案起了个名称（设计模式）。
注意：设计模式是需要大家通过经验的积累而获得的。

软件开发的设计模式分为三类（23 种）
1：创建型（创建类或对象的：例如：单例、工厂）
2：结构型（关注类的结构）
3：行为型（关注类的行为）

单例的目的：通过一个对象的使用（节省内存，提高效率）

  2. 不需要继承其他类

  • 防止反射和反序列化攻击

  • 延迟初始化

虽然枚举单例有一些局限性（如不能继承其他类），但在大多数情况下，它是实现单例模式的最佳选择。特别是在需要高度安全性的场景下，枚举单例比其他实现方式更加可靠
